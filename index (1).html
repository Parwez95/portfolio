01Profile

Engineer first. Automator by instinct.

An engineer who moved into software — and kept the process thinking. Mumbai · working hybrid

I integrate AI into software in a way that survives real users — automation over repetition, and measurable behaviour over demos.

My work sits across two worlds that turn out to be the same discipline: engineering automation and applied AI. At CitiusTech I design intelligent automation systems in Python, work with LLMs, RAG pipelines, agents and vector databases, and build the APIs that carry them — all inside healthcare software, where correctness is not optional.

Before that I came up through test automation: architecting end-to-end frameworks in JavaScript and Mocha, automating enterprise workflows and regression suites, and using AI tooling to make the engineering team itself faster. That path shaped how I build now — a system isn't finished when it runs, it's finished when it can be trusted.

I hold a BTech Engineer from North Maharashtra University, which is where the process-first thinking comes from: inputs, controls, tolerances, outputs. Today I apply the same lens to software pipelines and AI workflows.

How I build.

Operating principles
P-01

Automate the second time

If a task happens more than once, it becomes a script. If it happens constantly, it becomes a system.

P-02

Make it observable

Automation you can't see is automation you can't trust. Logs, stages and clear failure states are part of the feature.

P-03

Ground the model

Retrieval before generation, structured output, and a defined boundary for what the AI is allowed to answer.

P-04

Leave it maintainable

Documented, tested and handed over — so the team runs it without me and the next engineer improves it.
